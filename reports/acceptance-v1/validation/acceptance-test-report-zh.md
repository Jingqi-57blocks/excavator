# Excavator × WCP 第一版全面验收报告

## 1. 最终结论

**结果：通过，可作为第一版基线。**

通过含义：Excavator 能在同一 WCP 源码快照上，为产品角色和工程角色生成结构完整、内容足够详细、问题章节不包含建议、关键事实可回到当前源码验证的报告。该结论不表示 WCP 线上行为、数据、外部服务或其全部自动化测试已经验证。

### 产品角色

- WCP 产品 Overview
- 请假管理
- 工时管理

### 工程角色

- 账单与发票

- 招聘与候选人

共生成 **13 份报告**，总大小 **195,783 bytes**，总行数 **3,061**。

## 3. 通过标准

1. 产品功能报告覆盖边界、用户旅程、规则、状态、角色、数据、副作用、失败、任务、当前问题、术语和覆盖。
2. 工程报告覆盖 runtime、技术栈、入口、调用路径、权限、数据库、事务、通信、配置、任务、测试和当前技术问题。
3. Overview 的问题章节描述系统级现状；功能报告的问题章节只描述该功能当前问题。
4. 问题章节不包含处方性建议。
5. 每份报告质量得分不低于 85/100。
6. 报告源码路径存在，显式行号有效。
7. 关键数字、状态、权限和风险通过源码断言。
8. 不出现关键事实错误；静态分析限制只能进入覆盖章节或 Excavator 验收报告，不能进入目标项目的问题章节。

- 请假 10 类类型、9 个状态、14 个请假 API、4 个额度 API、四类创建附件要求和撤销额度事务；

- 账单/发票状态、权限、金额/评论边界、row lock、人工账单和事务后通知；
- 绩效客户临时入口、阶段映射矛盾、对象权限表达式、cron 和无 timeout 远程 auth client；
- 招聘职位 transaction、候选状态、客户分享、异步邮件、Beisen 与 AI 状态；
- OAuth2 授权码、redirect、PKCE、JWT、配置 clients、实例内存 code 和 `pricinpal` JSON tag。

## 8. 测试中发现的 WCP 当前问题

除了各报告的问题章节，本次验收额外定位到：

- 拉美 PTO 生产常量的全职提醒阈值为 166，但 `alert_test.go` 仍按 200 断言。
- 尝试执行该 Go 测试包时，环境需要联网下载 Go 1.23.10 toolchain，因此测试未运行；没有把它计为通过或失败。

## 9. 第一版仍允许的限制

- 部分 Feature Context 达到 500 节点上限，候选范围包含噪声；报告依靠源码断言避免把候选关系直接写成事实。
- 目标 WCP 服务、数据库和第三方依赖没有启动；没有线上流量、数据质量、消息送达和性能结论。
- WCP 自身全部测试未执行。
- 13 份报告经过本轮独立验收 harness，而不是全部写入同一个完整 claims/workitems/timeline authoring run。

这些限制已明确标注，不构成第一版报告生成验收失败。

## 10. 最终判定

第一版通过。最重要的质量门槛已经满足：

- 报告不再因为 Context 很大而退化为概括性说明；
- 系统级和功能级问题有独立章节；
- 产品版与技术版关注点明显不同；
- 关键数字和问题可由当前源码验证；
- CodeGraph 可选，Source-only 可以完成准备；
- 暖运行无重复图查询和源码读取。
