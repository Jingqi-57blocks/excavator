## 逐份判断

### WCP 产品概览

通过。能够解释系统不是单一工时工具，而是员工、项目、工时、请假、费用、账单、绩效、招聘和身份能力组成的平台；系统级风险集中列在独立章节。

### 请假管理

通过。覆盖十类假期、九个状态、申请—审批—撤销—完成旅程、额度和跨年分配、地区规则、附件、通知和当前问题。源码复核确认创建时硬性要求附件的是 Sick、Maternity、Prenatal、Marriage，不包括 Funeral。

### 工时管理

通过。覆盖个人填报、修改、软删除、Jira、团队月度确认、快照、提醒、导出和账单交接，并明确 UI 规则与 API 规则不一致。

### 账单与发票

通过。覆盖负责人确认、销售确认、费率、折扣、人工账单、发票关联、付款状态、作废和当前问题。

### 绩效评价

通过。覆盖周期、自评、同事评、主评、客户评价、结果发送和一对一；权限表达式和阶段映射矛盾均单独列出。

### 招聘与候选人

通过。覆盖职位、候选池、项目推荐、面试、客户空间、分享 key、外部同步和 Onboarding；多套状态体系和敏感数据边界已列入当前问题。

## 第一版允许的小问题

- Overview 信息密度较高，完全非技术读者仍需要通过目录按章节阅读。
- 部分源码中的业务名（PTO、BTO、BillingSnapshot、Main Reviewer）保留在报告中，但均有术语解释。
- 静态报告无法说明线上使用频率、任务成功率、真实数据和外部服务送达率，均已标为不可回答。

目标项目的风险/当前问题章节只保留可归因于 WCP 源码、测试或文档的现状。CodeGraph、Excavator、未解析关系、源码回退和静态审阅限制仅出现在覆盖章节或验收报告；本轮检查为 0 处混入。
