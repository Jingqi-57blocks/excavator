# code → knowledge 改造方案

从零重新设计「仓库 → 可辩护知识」这一段的层次架构。**范围止于 knowledge**：knowledge → 报告（撰写、claim 绑定、报告审计、HTML 导出）不在本方案内，唯一跨界的约束是——撰写层只能陈述它能绑定到**可引用单元**的事实，所以本方案必须产出可引用单元。

方案基于五路调研（外部索引底座、功能定位文献、LLM 仓库理解、完整度记账、我们自己的逐层清点）与两路并行设计的整合。**证据、外部引用与不可引用清单见附录（第十一节起）**，设计正文里每处外部依据都能在附录找到对应小节。所有 `path:line` 锚点核于 `819853f`。

## 一、为什么要重做，而不是继续打补丁

今天一个代码单元进入功能范围的条件，是查询词在四个文本列上的子串匹配（`src/codegraph/codegraph.ts:186-204`，调用点 `src/context/context.ts:366-369`）。而所有结构机制——扩展（`context.ts:374`）、prune 捞回（`feature-prune.ts:206-224`）、席位地板（`prune-module-floor.ts:43`）——**遍历的都是已经能从词法种子到达的那个池子**。

于是：**没有词法命中、且离命中不到两跳的单元，是构造性不可达**——不是预算不够，是形状决定的。

而文献早有这个问题的名字，叫 **filter vs rank**，并且给出的角色分配**和我们正好相反**：

> Dit 等人：*"Dynamic analysis generally yields good recall, while textual analysis has good precision… use dynamic analysis to **filter** the program elements for textual analysis instead of ranking all the program elements."*
>
> Dora：*"**structural** information to focus exploration and **lexical** information to prune."*

两处都是**召回强的信号负责准入，精度强的信号负责排序**。我们把精度强的那个当了唯一准入器。

实测的伤害是**不对称**的（`wcp`，词 `leave/holiday/vacation`，参考读数非定律）：

| 读数 | 值 |
|---|---|
| 误准入（相近词无关功能） | **1 / 1241** |
| 零准入 | **一个 486 符号的模块整体缺席** |
| 另一目标（provital） | 639 个约定恢复出的路由**全部不可达**，因为索引对该语言零节点 |

所以复杂度预算应该花在**零准入**一侧。

## 三、核心裁定：准入被废除

两路设计在这里正面冲突。归属轨道的规则是：

> **没有东西需要准入，所以没有准入。分母里的每个单元天生就是候选。信号只计分；分数只在预算内分配席位；零分的模块失去的是席位，不是存在——它的零是一行带理由的记录。**

原来混作一团的概念拆成三个，各有其主：

| 概念 | 含义 | 归属 |
|---|---|---|
| **可达性** | 一个单元能否出现在候选记录里 | 单元分母，**构造上完整** |
| **分数** | 信号把它与本能力关联得多强 | 计分通道，**谁都不能当闸** |
| **席位** | 它是否进入 L6 要读的有界工作集 | 分配器：预算 + 公平地板，**每次挤出都记账** |

**为什么废除而不是加准入路径。** 保留闸——哪怕加了非词法的准入路径——只是把失败类缩小半径：任何目标上只要索引、native-graph、pack 三者都不覆盖某模块，零准入就原样复现。而**唯一能让「不可达」结构性不可能的办法，就是没有闸**。

**代价已定价。** 输的那个选项会让设计把预算花在枚举准入路径上，而不是化解这个类；并且保留文献警告的极性倒置。

另一条支撑：记账哲学（不许有第四态，每行必落桶）在新规则下**被更好地满足**——全体计分让「模块从记录中缺席」变成**不可表达**，这比「模块的缺席被记录下来」更强。

**「零准入」只作为一个读数存活**：某模块所有单元都计了零分。那是一行产物，不是一次缺席。

## 四、三条贯穿全局的法则

### 4.1 输出法则（回答「静默出空」这一整类）

> 每一层的输出都是一个产物，**只有一个写入点**，类型是闭合判别联合 `Built | Unavailable{reason}`，理由取自该产物模块自己拥有的闭合枚举。**「没运行」是一个被写下来的状态，绝不是一个不存在的文件。** `Built` 内的每个枚举都带完整度块，记录所有让它变短的预算、上限或失败。可能截断的生产者，**把完整度日志作为必填参数**。每个台账都是冻结输入（被摘要）和审计输入（被检查）——缺失或不平衡的台账会让闸失败。

代码里今天**对的和错的写法并排存在**：`scopeCensusUnavailable` 在失败路径上照写（`run.ts:465`），而 `crossrepo-links.json` 只在 `if (crossRepo)` 时写（`:473`），生产者返回裸 `null`（`:111`）——**就在一段解释「为什么这样不对」的注释下方十二行**。法则把前者推广，把后者作为一种形状删除。

「必须被消费」这一条有实测支撑：CycloneDX 声明不完整性的 `compositions` 机制存在十年，**61691 份野生 SBOM 里只有 0.10% 用了**，而标准评分器从不读它。一个没人读的残差字段不会被使用。

### 4.2 分母法则（全体计分赖以可审计的那条）

> 分母只能取自**严格更早层**的台账产物，且该台账**记录自己的完整度**；消费方嵌入「哪个台账、哪个摘要、完整度块是什么」。**分子可以来自任何地方，分母只能来自台账。**

指定台账：`ledger/files.json`、`ledger/mechanisms.json`、事实库信封。**不是** `GraphSummary.roots`，不是范围文件清单，不是证据目录。

执行靠**代码形状**而非纪律：`RowSet<K>` 私有构造函数 + 三个台账访问器，census/义务/归属构建器只接受 `RowSet`，于是**裸 `string[]` 不再通过类型检查**。

这条同时化解一件我先前修错了一半的事：「分母取快照」听起来对，但快照本身是 `min(全部, 上限)` 且**上限无声**（`snapshot.ts:211`、`:237`）。所以正确的规则不是「指向哪个既有集合」，而是**分母必须记录自己的完整度**。

### 4.3 三态法则

```
ExclusionRule = "fixed-excluded-dir" | "gitignore" | "oversize" | "unsupported-name"
              | "no-mechanism" | "non-unit-kind" | "zero-score" | "budget-displaced" | …
RowStatus     = {state:"counted"} | {state:"excluded", rule} | {state:"unexplained"}
```

`summarize` 是**唯一的**摘要构造函数，并断言 `total = counted + excluded + unexplained`。`unexplained` 是诚实残差——冻结时是劝告，**永不可删、永不被压平**（反面样板是 JaCoCo 内部知道 `isNoMatch()` 而 XML 写出时丢掉它）。

一处因废除准入而变强：在归属那一节里，**「进了分母却没到过计分器」的单元在代码形状上不可表达**（只有一个遍历 RowSet 的计分循环），所以那里 `unexplained > 0` 意味着产物损坏，是**错误**而非劝告。

## 七、需要拍板的一处张力

**P14 被定为「诚实地限界」而不是化解。** 结构探针的语言注册表今天只有 TypeScript / Tsx / JavaScript / Go（七个扩展名，`condition-extract.ts:60`），Perl 另有专门后端；**Python / Java / Ruby / PHP / C# 全部返回 `unavailable`**（`decision-probe.ts:52`），而消费方直接丢弃（`read-obligations.ts:257` 的 `if (fn.probe !== "decision") continue`）——总量可见，逐函数不可见。

也就是说：**结构层覆盖了明确低优先的语言，漏掉了明确高优先的语言。**

方案的立场是：注册表让「补一种语言」变成一次编辑 + 一次依赖审计，台账让缺口变成**每语言每机制的一个数字**，但**真正给常用语言加语法解析被列为范围外**，理由是「曝光先于机制」。

我认为这个顺序是对的（否则加了语法也不知道补没补全），**但「什么时候补、先补哪几种」现在没有排进切片，这一条需要决定。**

---

## 八、非目标

**先前裁定全部维持，无一被推翻。**

- **不做语义图 / 本体层。** 事实词表按 Kythe 的方式避免逐语言扩展：13 个闭合 kind + 生产者自有的不透明 `subkind` 字符串 + 一个 `unmapped` 计数器代替新增 kind。通道是机制而非含义；仓内 df 是一次测量而非词表——**「是不是英语词典词」是一个关于词的世界本体，而它恰好在我们的核心失败模式上失效**。
- **不给曝光加审计计数。** 线索是可引用事实，不是阅读额度。
- **不加「窗口必须被引用」闸**——这正是 L6 与 L7 保持两层的原因。
- **不嵌 Python 运行时；不把模型生成的标签写进核心产物。** 别名以「被记录的输入」进入，永不作为派生事实。

**有意不做（及理由）：**

- **任何形式的准入闸都不回来**，包括对总分设阈值——那是换了名字的闸（文献里唯一支持前置过滤的实验，其协议**结构上看不见闸的代价**：阈值在 gold 集上调，且把「相关的全被滤掉」的案例直接丢弃）。
- **核心内不用 embedding、学习型排序器、网络或模型调用。**
- **不做执行/动态准入**——文献最偏爱的召回强准入器要求**运行**被分析的功能，与只读目标约束冲突。记录在此以免被重新发明。
- **不强行给沉默模块塞席位**——给**线索**不给席位：席位花的是模型阅读预算。保留 Brakeman 的可平移教训（**放宽要在输出里点名**），拒绝它「假定全都是」的经济学。
- **不为常用语言新增语法**（见第七节，待定）。

## 九、诚实边界

**建成之后，引擎可以声称：**

- **已发现的没有被静默丢掉。** 走查看到的每个文件都在某个桶里（L0）；每个（文件 × 机制）对都有状态（L1）；分母里每个单元都有结局——得席位、带理由被挤出、或带理由为零（L5）；每个 census 平衡，否则 run 失败（L9）。
- **分母相对于一个陈述过的范围是完整的，并且陈述自己的不完整。** 上限与截断被写进继承它们的产物，而不是靠考古发现。
- **残差可见且可引用。**

**仍然不可以声称：**

- **全都被发现了。** 计分会漏；线索可能差；一个与仓库任何表面都不共享词汇的能力，可以在所有地方计零分，然后被诚实地报告为「未定位」——而它确实存在。
- **计分在核心失败模式上得到过验证。** **没有任何文献测量过「代码标识符与查询不是同一种自然语言」时的检索表现**（已核实的空结果）；M2/M5 是我们自己的目标上的自己的读数，**两个目标不构成一个总体**。
- **对优先语言的符号级理解。** 语法切片落地之前，Python/Java/Ruby/PHP/C# 的函数在探针上是 `unavailable`——**区别在于 S3 之后这是台账里每语言的一个数字，而不是一片沉默**。

**被点名的假设，以及没有它会怎样：**

| 假设 | 没有它 |
|---|---|
| 该模块的语言有 CodeGraph 索引 | 分母依次退到 native-graph 单元、约定处理器区间、文件粒度单元——**可见地、逐生产者地**写在产物的 `byProvider` 块里 |
| 某个框架 pack 认得这个目标（今天：gin、express、Catalyst） | `C-conv` 没有表面；pack 信封读作 `not-detected`；模块理由可以点名 `channel-unavailable` |
| 操作者/模型给出可用的别名 | 逐别名计数器暴露 `dead`/`flood`/`unanchored`；派生扩展救回一部分（由 M5 测量，**绝不假定**）；零词汇的 run 用入口地图回答 |
| 目标是多模块 | crossrepo 写它的 `single-module` 信封；分配器的地板是可证明的空操作；**没有东西悄悄消失** |

## 十、风险登记

1. **中心赌注可能是错的：排序 + 地板在同等预算下给出的席位集比今天的「闸 + 扩展」更差。** 全体计分买到了可达性，但如果席位集退化，方案就是拿一个**可见的失败**（空范围）换了一个**不可见的失败**（更差的范围）。
   **最便宜的揭示：M4** —— 在 S8 的门关上**之前**，拿它与 S6 的 v0 记录在 eval 语料和 wcp 上做同等预算的席位集 diff。这就是 S6 必须在 S8 之前、且 S8 由读数而非评审把关的原因。

2. **记账变成装饰。** 台账与理由可能重演 CycloneDX 的模式：一等的不完整性声明，没人读（0.10% 采用率，评分器从不读它）。
   **最便宜的揭示：** 一个故意不平衡的 census 夹具 + 一个故意被跳过的检查族——冻结**必须**失败，审计清单**必须**点名这次跳过。**任一处过绿，消费强制就是坏的，所有台账都是死重。**

3. **词汇无关通道在常用语言上是空的。** `C-conv` 的论证（协议词汇能扛住标识符语言漂移）**是从机制论证的，没有文献支撑**；而 wcp 那 926 个 route kind 节点**未核实**是否真是 HTTP 路由。若它在 wcp 与 angels-pizza 上都零 sole-source，零准入的修法就只剩闭包（V2）与线索（V3）。
   **最便宜的揭示：** M2 的 `soleSource` 计数器，三个能力 × 两个常用语言目标——**从每次 run 的一个产物里就能数出来，不需要 gold 集**。

第四条更便宜的隐患，记录在此：**全体计分的 prepare 成本**。按实测规模（wcp 排除结构 kind 后约 12908 单元，**而非假设的 10 万**）风险低，且分层规则是结构性的而非阈值触发的，但这个界仍是 S8 要取的**第一个**读数，因为它错的话能最便宜地推翻方案。

## 十一、附录：外部索引底座：SCIP/LSIF · Kythe · Glean · CodeQL · Joern · stack-graphs

**层次划线的位置各不相同，但都在「语法 / 名字解析 / 类型解析」之间划了线。** SCIP 的前端做语法加尽可能多的本文件内解析，类型解析显式地是**后续、可选**的一步。

**部分覆盖的表达能力，四种立场：**

| 立场 | 代表 | 代价 |
|---|---|---|
| 中性层 + 保真度损失 | LSIF/SCIP | 语言特有信息被压平 |
| 占位符代替省略 | Joern/CPG | 占位符自身要被解释 |
| 逐语言全保真 + **派生**的中性视图 | Glean（94 个 `.angle` 文件、`code.Entity` 18 分支和、`codemarkup` 约 35 个通用谓词逐语言手工映射） | O(语言 × 通用谓词) 的手写映射，**可证明不完整且沉默地不完整**（`EntitySource` 只映了 2/18） |
| **完全没有中性层** | CodeQL | 基础关系之上的一切都写 N 遍 |

CodeQL 的共享机制值得记：**是文本复制粘贴同步而非 include**，`config/dbscheme-fragments.json` 列出 5 个文件，**约 10 种语言里只有 5 种被这个同步 linter 覆盖**。

**对我们最有用的一条：** SCIP 明确规定 `local ` **不是**未解析标记——它是「本文档内、外部不可访问」的语义。把「作用域是局部的」和「我没解析出来」分开表达，是我们 L2 溯源该抄的形状。

## 十二、附录：功能定位 filter vs rank（对本方案影响最大的一路）

### 12.1 极性

这个领域给「什么信号负责准入」的答案，**和我们相反**：

> Dit 等人 `[documented]`：*"Dynamic analysis generally yields good recall, while textual analysis has good precision… use dynamic analysis to **filter** the program elements for textual analysis instead of ranking all the program elements."*
>
> Dora `[measured, 仅摘要]`：*"**structural** information to focus exploration and **lexical** information to prune."*

**召回强的信号准入，精度强的信号排序。**

### 12.2 三条限制我们能借多少

1. **绝大多数 IR 缺陷定位文献没有准入闸。** BugLocator / BLUiR / AmaLgam / learning-to-rank 全都给**每个文件**打分。在那里词汇不匹配只会导致排名差，**永远不会返回空**。它们的 delta 从未在「可能返回空」的设计上测过，**不可平移到准入决策**。

2. **唯一真去测「前置过滤」的那篇，把过度过滤的代价藏了。** 过滤阈值**在 gold 集上调**，调到只有 **66%** 的功能还留下至少一个 gold 方法；而头对头的对比表把「相关的全被滤掉」的功能**直接丢弃**。所以「过滤优于排序」这个结论，来自一个**结构上看不见闸的代价**的实验协议。我们已经在真实目标上付过一次这个代价。

3. **绝大多数彻底失败的案例里，词在文本里，是「选词」失败了。** Rahman 等人，2320 份报告筛出 939 份：**Hit@10 为 0.00%** 的那批，用 oracle 从**同一段文本**里重选词后达到 **78–93%**；实用启发式只救回 27–34%。有效词的特征：**更低频、更少歧义、名词、来自描述而非标题**。→ **选词是一个层，不是预处理细节。**

### 12.3 结构优先的入口（不靠词汇定位）

**Brakeman 的实际做法（含对我们旧笔记的纠正）：** 我们此前记的 `loose_action` **在源码里不存在**。Brakeman 实际是**放弃**用约定恢复路由作准入闸——*"this is not perfect… so now it assumes all controller methods are actions"*——并把这次放宽做成一个**具名、用户可见的告警**（`:allow_all_actions`）。**可平移的教训比原来那条更强：约定恢复不确定时，成熟工具放宽成超集，并在输出里点名这次放宽，而不是把它埋进分数里。**

**JackEE 的 4× `[measured]`** 是真的，但那是**分析可达性的完整度、没有查询**，不是检索精度，不可当作定位数字引用。

### 12.4 一个已核实的空结果

**没有任何研究测量过「代码标识符与查询不是同一种自然语言」时的检索表现。** 我们最核心的失败模式**没有文献可借**——在这一点上声称有外部支持就是过度声称。

### 12.5 不可引用清单（每条附取消资格的理由）

| 数字 | 为什么不能用 |
|---|---|
| EMSE web-mining FL 的「高达 87%」 | 阈值在 gold 集上调；失败案例被排除在对比之外；87% 是 1–87% 区间里最好的单格，区间内**有些变体比基线更差** |
| 任何跨系统的「effectiveness measure」（首个相关项排名） | **正是我们先前踩的坑**：Eclipse gold = 补丁方法（45 个功能）；Rhino = prune 依赖文档映射（241 个，大得多）；jEdit = commit 方法（150 个）。**gold 集更大就让这个指标更好，与技术优劣无关** |
| BugLocator「62.60% top-10」 | 本身已是词法+历史的混合体；查询是**含栈迹和类名的完整缺陷报告**；是 12863 里的 top-10 |
| BLUiR / AmaLgam / Ye LtR / Ye embeddings / Dora 的 delta | 只读到摘要，且全在同一个 Eclipse/AspectJ/SWT/ZXing 家族上 |
| GenTest「82% 切分准确率」、AMAP「+57%」 | 标识符 oracle 准确率，**两者都没测下游检索 delta** |
| Refoqus「84%」 | 那是「改善**或保持**」，两者的比例被隐藏 |
| BLIZZARD「+56%」 | 是逐项目区间的最高值，区间从 7% 起 |
| JackEE「4×」 | 分析可达性完整度，无查询 |
| Rahman「78–93% Hit@10」 | **需要 ground truth**；作者自述「不能用于实际场景」 |
| 任何 CodeSearchNet docstring split 的数字 | 查询就是函数自己的 docstring；只有 99 条专家查询集在题上 |
| Furnas「< 0.20 / 80–90% 失败率」 | 是人给日常物件命名，不是开发者给代码命名 |

## 十三、附录：LLM 时代的仓库理解

### 13.1 SWE-agent 的 ACI 消融（最可平移的一组数字）`[measured]`

SWE-bench Lite，GPT-4 Turbo：

| 变体 | 解决率 | Δ |
|---|---|---|
| 文件视窗 30 行 | 14.3 | −3.7 |
| **文件视窗 100 行** | **18.0** | — |
| 文件视窗 整文件 | 12.7 | −5.3 |
| **搜索结果摘要化** | **18.0** | — |
| 搜索结果迭代式 | 12.0 | −6.0 |
| **完全不搜索** | 15.7 | −2.3 |
| 编辑器带 lint | 18.0 | — |
| 编辑器不带 lint | 15.0 | −3.0 |

**两个方向都掉**（视窗太小和太大都不行），而且**迭代式搜索比完全不搜索还差**——agent 会一直 `next` 直到穷尽所有命中，把预算烧光。端到端：SWE-agent 18.00% vs **BM25 RAG 2.67%**。

**定位失败的形状** `[measured, n=248]`：**「在对的文件里找错位置」12.9%** vs **「压根没打开对的文件」2.4%** —— 5 倍差距。

**它的具体常数（全部无模型、可直接平移）：** 视窗 100 行 / 重叠 2；`goto` 把目标行放在视窗 1/6 处；`search_dir` **把输出压缩成 `path (N matches)`，丢弃匹配行**，超过 100 个文件就拒绝并要求收窄；观测截断 100k 字符，编辑器内 16k。

### 13.2 溯源：三家的做法与共同的缺口

- **SWE-agent** `.traj` 的 `query` 字段**就是那一步发给模型的确切消息列表**——是字面收据而非重建；每一步都写，崩溃也留证。
- **OpenHands** 追加式事件日志，一事件一文件；**压缩是墓碑而非删除**——`Condensation` 事件记录 `forgotten_event_ids`，所以**既能重建模型压缩后看到的，也能重建被藏起来的是哪些**。它的 prompt 段落被**逐字节**快照测试钉死。
- **Copilot** 只有 UI 下拉里的文件+区间引用，**每次回答检索到的 chunk 集从不持久化**。

**三家共同的缺口：都记录「什么进入了上下文」，没有一家陈述「什么没被检查」。** Copilot 是唯一会**告诉模型自己的视图不完整**的（"may be truncated"、"Response may be less accurate"）；OpenHands 是唯一在工具结果上给出机器可读 `truncated: true` 的。

### 13.3 两条与我们直接相关的

- **Copilot 的本地缓存身份是 size+mtime，不是内容哈希**（`getFastContentVersionId()` 返回 `` `${size}-${mtime}` ``）。这与我们 P10 是同一个病。
- Copilot 里那个**纯本地、确定性的 `PersistentTfIdf` 代码还在，但已从所有检索路径上摘掉**——**他们删掉的正是我们要保留的那一层**。

### 13.4 Claude Code 的立场 `[documented]`

> *"Rather than pre-processing all relevant data up front, agents… maintain lightweight identifiers (file paths, stored queries, web links, etc.) and use these references to dynamically load data into context at runtime using tools."*
>
> *"…glob and grep allow it to navigate its environment and retrieve files just-in-time, **effectively bypassing the issues of stale indexing and complex syntax trees**."*

以及那条元数据论证：*"the presence of a file named `test_utils.py` in a `tests` folder implies a different purpose than a file with the same name located in `src/core_logic/`"* —— 路径本身是信号。

**注意模型依赖：** SWE-agent 与 OpenHands 的循环**一步都不能没有模型调用**；OpenHands 更把 **LLM 放进了它的边界机制里**（压缩器需要模型调用），所以没有无模型的有界视图路径。Copilot 默认路径需要网络 + 服务端 embedding，且端到端受 auth 门控。

## 十四、附录：完整度记账——残差何时成为验证失败

### 14.1 六条横切结论

1. **只有 in-toto 和 Kyverno 真正实现了「残差即失败」**，而 in-toto 里它是**布局作者必须记得敲的一个字符串**。SLSA 删掉了它的完整度标志；CycloneDX/SPDX 让残差声明可表达但可选且无强制；Nix 没有残差概念（它**预防**而不审计）；**Bazel 的 `.d` 扫描是唯一一处「残差即失败」真的是默认的地方**。
2. **反复出现的失败模式是：正向规则各自沉默。** in-toto 的 `MATCH` 在对方 link 缺失时返回空消费集；cosign 的 CUE/Rego 策略在 attestation 缺失时**根本不执行**；Kyverno 的 `imageReferences` 干脆不匹配。三处都靠一个**独立的、手写的、在匹配逻辑之外的**残差守卫——**没有一个是匹配语言本身提供的性质**。
3. **「残差即失败」被反复以易用性为由交易掉，而且有据可查。** in-toto 的隐式 `DISALLOW *` → 隐式 `ALLOW *`（决策者原话：*"mostly a bet for usability"*，当时的安全反对被驳回并留在记录里）；SLSA v0.2 的 `completeness.materials` → v1.0「由 `builder.id` 隐含」；Bazel 的 `hdrs_check` → "Deprecated, no-op"；Nix `--rebuild` 默认关。
4. **检查能成为默认的地方，是因为它被做便宜了或做成结构性的，不是因为被规定了。** Bazel 的 `.d` 扫描搭在编译器本就输出的 `-MD` 上；**Nix 的固定输出派生把哈希做成了「获得网络能力的前提」**，所以没人能跳过。两者都避免了让任何人 opt in。
5. **单一的「未解释」桶会退化成垃圾堆，2026 的规范正在拆它。** CycloneDX 早已区分 `unknown`（看了，不确定）与 `not_specified`（没说）；SPDX 的 `NOASSERTION` 把「试过没成功 / 没试 / 故意不说」三态混在一起且明确拒绝让你推断是哪个；**CISA 2026-07-29 的修订要求拆成 `unknown` / `redacted` / `not applicable`**，理由是这个选择告诉接收方的信息「关于目标软件**和 SBOM 作者本人**」。
6. **两层默认的不对称是部署强制的标准形状。** policy-controller 的 `no-match-policy` 代码默认 `deny`（内圈失败关闭），但**命名空间是 opt-in**——外圈根本没有记账，所以未标记命名空间里的产物**连残差都算不上**。

### 14.2 那条最承重的实测 `[measured]`

「No Edges, No Verdict」，78612 份 SBOM、1782 个 forge、77092 份可解析：

- **52.9% 完全不声明任何依赖信息**
- **61691 份 CycloneDX 里只有 59 份（0.10%）带 `compositions` 块**声明图完整度，且多数声明的是含 `unknown` 的混合

作者结论原话：*"Producers do not declare incompleteness because no specification requires them to, which leaves consumers without a machine-readable signal to route semantics on; until that changes, the open-world reading is the only safe default."*

**为什么是 0.10%** `[documented]`：度量层对声明层是盲的。质量评分器 `sbomqs` 的评分项里 **`composition` / `aggregate` / `NOASSERTION` 出现零次**。诚实声明 `aggregate: incomplete_first_party_only` 的 SBOM 与什么都不说的**得分完全一样**。→ **一个没人消费、缺了也不失败的一等残差机制，十年后采用率千分之一。**

### 14.3 两个罕见且值得抄的形状 `[documented]`

- **SPDX**：`filesAnalyzed: false` 让 `packageVerificationCode` 的基数变成 **0..0（必须省略）**，并且该 package **不得包含任何文件**。**声明「我没看」就禁止你产出那个暗示「我看过」的产物。** 而验证码自带声明残差：算法的排除文件清单与哈希一起发布（`PackageVerificationCode: d6a770ba… (excludes: ./package.spdx)`）。
- **CycloneDX**：「无依赖的组件**必须**被声明为图中的空元素；**未出现在图中的组件可能有未知依赖，实现应当把它当作不透明，而不是当作『无依赖』的指示**」。**格式强迫你区分「没有」和「不知道」，而不允许用「缺席」兼任两者。**

### 14.4 反面样板

- **JaCoCo** 的分析器内部知道 `noMatch`，**XML 写出时把它丢掉**。
- **Semgrep** issue #11605：`nosemgrep` 抑制在默认输出里被尊重，**在 `--sarif-output` 里不被尊重，而两种情况退出码都是 0**。
- **TypeScript / ESLint 的反向形态**（值得注意的对照）：`@ts-expect-error` 在被抑制的行没有错误时报 `Unused '@ts-expect-error' directive.`，ESLint v9 的 `reportUnusedDisableDirectives` 默认 `"warn"`。**让「排除」本身成为会失败的东西**——是「残差失败」的镜像框架。

## 十五、附录：现状清点里改变了设计前提的四条

完整清点含 `path:line` 锚点，结论已并入 `code-to-knowledge-design.md` 的层次表与问题册。这里只留清点独立发现、且改变了设计前提的四条：

1. **`maxFiles` 是完全静默的截断**（`snapshot.ts:211` 裸 `continue`、`:237` 多根循环 `break` 可丢掉整个根），**每个 census 分母都经 `allowed_files` 继承它**。→ 修法不是「分母取快照」，而是「**分母必须记录自己的完整度**」。

2. **结构探针的语言覆盖是反的**：`AST_LANGUAGE_BY_EXTENSION` 只有 TS/Tsx/JS/Go（七个扩展名），Perl 另有专门后端，**Python/Java/Ruby/PHP/C# 全部 `unavailable`**；而 `read-obligations.ts:257` 的 `if (fn.probe !== "decision") continue` 把它们**全部丢弃**——总量可见，逐函数不可见。

3. **只有一对注册表有漂移测试**（`tests/search-corpus.test.ts:17` 钉 `SOURCE_EXTENSIONS ⊆ TEXTUAL_EXTENSIONS`），AST 注册表没人比对 → **一种语言可以「被扫到、被搜到、结构上隐形」而测试全绿**。

4. **结构信号全都在遍历 `nodes`**（已能从词法种子到达的池子），所以只能**排序**和**捞回**，不能**引入**——「不可达」是构造性的，不是预算性的。

清点也确认：`scopeCensusUnavailable`（在失败路径上照写）与 `crossrepo-links.json`（`if (crossRepo)` 才写、生产者返回裸 `null`）**并排存在于同一个文件**，中间只隔十二行注释——**代码里对的和错的写法同时存在**。
